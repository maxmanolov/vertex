# Vertex feature matrix

Living comparison against OptiFine 1.7.10 (HD Ultra line), maintained as features land.
Status values: **missing** / **in progress** / **matched** / **surpassed** / **excluded** (with justification).
All Vertex implementations are clean-room: designed from vanilla sources and mappings, public
format documentation, and observable behavior only (see docs/ARCHITECTURE.md for the policy).

## Rendering and chunk pipeline

| Feature | Purpose | Vertex status | Notes |
|---|---|---|---|
| Dynamic lights | Held/dropped light sources illuminate surroundings without placing blocks | **matched** (0.2.0) | Feature-complete for held items (all players): per-frame collector publishes sources, movement re-marks sections through the bounded priority path (tracker diffing unit-tested, capped), falloff engine on every brightness lookup. Soak-verified armed with zero failures. Dropped items and burning entities documented as follow-up scope; visual confirmation rides the same fly-through as multicore. |
| Interactive render priority | Rebuild the chunk section you just edited immediately instead of waiting on the throttled queue | **surpassed** | Not an OptiFine feature at all. Reach-gated, boundary-aware, capped 4/frame. Active since 0.1.0. |
| Fullbright | Max-brightness rendering that also skips light-triggered chunk rebuilds (PvP-client staple) | **surpassed** (0.3.x) | Not an OptiFine feature. `fullbright` key (default off) + a Video Settings button. Brightness overrides at the existing getMixedBrightnessForBlock hook (one volatile read when off); the perf half skips RenderGlobal.markBlockForRenderUpdate - the light-only re-mark path - reducing light-triggered section rebuilds; measured honestly, the skip catches the notifyLightSet path only, and some light-driven churn flows through other mark paths (#118 has midnight fixture measurements). World light logic (mob spawns, crops) is untouched. Skip counter in diagnostics (fbSkippedRemarks); toggle transitions reload renderers so the change is immediate. |
| Freelook | Hold a key to orbit the camera without turning your character (PvP-client staple) | **surpassed** (0.4.x) | Not an OptiFine feature. `freelook` config key (default on; the mechanic is inert until the key is held) plus a real rebindable KeyBinding in the vanilla Controls screen under Miscellaneous (default Left Alt, persisted to options.txt like every vanilla binding). While held: the avatar's heading, movement direction and crosshair aim stay frozen and the mouse drives a third-person orbit (yaw unbounded for the full 360, pitch clamped +/-90, vanilla sensitivity arithmetic); on release the view snaps back instantly and the prior perspective is restored. The rotation spoof brackets exactly the world-render call, so aim picking (getMouseOver) and every game tick read the true heading; no packets change - the locked heading is simply unchanged rotation, the same wire traffic as standing still. Self-disables to vanilla on any failure. |
| HUD background controls | Hide the translucent backgrounds behind chat lines and the scoreboard sidebar (PvP-client staple) | **surpassed** | Not an OptiFine feature. `chatBackground` / `scoreboardBackground` keys plus ON/OFF buttons injected into the vanilla Chat Settings screen (under Multiplayer Settings), persisted to vertex.properties. drawRect is rerouted only inside GuiNewChat.drawChat and GuiIngame.renderScoreboard, so every other HUD rectangle is untouched; enabled behavior replays vanilla's exact GL sequence. GUI verified by screenshot probe (placement + toggle round trip incl. save); chat effect verified by in-world capture diff. |
| Toggle sprint | Tap sprint once to stay sprinting (PvP and parkour staple) | **surpassed** (0.4.x) | Not an OptiFine feature; mirrors modern Minecraft's native sprint-toggle accessibility setting, which 1.7.10 predates. `toggleSprint` key (default off; hot-reloads). While latched, Vertex holds the vanilla sprint keybind's pressed flag high once per frame, so every vanilla gate stays authoritative (forward key, hunger, blindness, collision, sneaking) and the player re-sprints the instant conditions allow - exactly as if the key were held. The latch starts armed when the feature is enabled; tapping the sprint key (default Left Ctrl, rebindable) pauses/resumes it, and taps are ignored while a GUI is open so typing never flips it. No movement logic or packets are touched; the untouched server keeps enforcing sprint legality. Latch flips counted in diagnostics (tsLatchFlips). Self-disables on any failure. |
| Multi-core chunk building | Tessellate chunk geometry on worker threads | **surpassed, default-on** (0.3.2) | OptiFine 1.7.10 has no true worker-thread tessellation; Vertex ships it on by default. Promotion gate closed 2026-08-06: structural verification (7,495/7,495 identical per-section audits, correct captures), hardened lifecycle (#73-#76, #91), the in-motion resort race found by the first human fly-through and fixed at root (#92/#95, A/B-verified over the crash site), then a clean human fly-through sign-off on the fixed pipeline. `multicore=false` in vertex.properties (or -Dvertex.multicore=false) opts out; restart to apply. Full history: docs/benchmarks/multicore-status.md. |
| Terrain renderer backends (VBO / shared arena) | Replace per-section display-list submission with batched buffer draws | **surpassed (experimental, opt-in)** (0.4.0) | OptiFine 1.7.10 keeps the vanilla display-list renderer. Vertex ships a staged replacement behind the `renderer` key (default `legacy`, restart to apply): `displaylist` (managed section-mesh transport, vanilla visuals and performance), `vbo` (per-section vertex buffers), `arena` (shared per-region buffers, baked section transforms, glMultiDrawArrays batching; translucent batches merge only consecutive walk-order runs so vanilla back-to-front draw order is preserved exactly). Measured at RD16: per-frame submission 8.26 ms (legacy) / 1.98 ms (vbo) / 0.30 ms (arena), ~51 draw commands vs ~1,700 (one per section), steady-state ~92 / ~306 / ~562 fps. Structural parity within the audit method's control noise, zero self-disables across the soak/churn/stress/world-transition gauntlets, Java 8 bytecode compatibility test-guarded. Design: docs/RENDERER.md. Numbers: docs/benchmarks/renderer-backends.md. |
| Smooth (time-sliced) chunk loading | Spread chunk rebuild cost across frames to reduce stutter | **in progress** | Folded into the multi-core pipeline as a budget policy on the same build queue (docs/ROADMAP.md #1). |
| Lazy chunk loading | Defer client chunk attach work | **in progress** | Folded into the multi-core pipeline (docs/ROADMAP.md #1); superseded as a standalone feature. |
| Fast Render (GL state batching) | Reduce redundant GL state changes per frame | **excluded** | Measured live with per-(unit,target) tracking (docs/benchmarks/fastrender.md, corrected for kyrofx #38): 45-49% of state calls are redundant, ~263 calls/frame, ~26 microseconds against a 16 ms frame (~0.16%) - far below the 5% threshold. Not worth the regression risk; counters remain in diagnostics for other hardware. |
| Render distance extension (>16) | Far render distance | **excluded** | Singleplayer-only benefit (servers cap view distance). The original blocker - display-list submission degrading sharply past 16 chunks - is gone under the 0.4.0 arena backend, so this becomes revisitable if demand exists. |
| Sky / stars / sun & moon toggles | Skip sky-pass draws for fps | **matched** (0.2.0) | `sky=false` in vertex.properties skips the whole sky pass. Per-layer split planned. |
| Cloud rendering control | Skip or simplify clouds | **matched** (0.2.0) | `clouds=false` skips the cloud pass entirely (vanilla only offers fast/fancy via graphics). |
| Weather rendering control | Skip rain/snow rendering + splash particles | **matched** (0.2.0) | `weather=false` skips renderRainSnow and rain particle spawning. Server weather state is untouched. |
| Void fog / depth particles control | Remove void fog particle churn | **matched** (0.2.0) | `voidParticles=false` skips doVoidFogParticles. |
| Texture animation control | Stop per-frame texture re-uploads (water/lava/fire/portal) | **matched** (0.2.0) | `textureAnimations=false` skips TextureMap.updateAnimations - one switch today; per-animation granularity planned. |
| Fog control (off/fast/fancy) | Reduce fog fill cost / visibility preference | **matched** (0.2.0) | `fog=false` disables distance fog via a GL-mode-aware tail hook on setupFog; lava/water/blindness density fog is preserved. Fast/fancy hint control judged not worth it on modern GPUs. |
| Particles fine control | Finer than vanilla's all/decreased/minimal | **matched** | Covered by the combination of vanilla's three-level setting and Vertex's weather + voidParticles controls; further per-type granularity judged marginal and excluded. |
| Fast Math | Cheaper trig via smaller lookup table | **excluded** | Benchmarked (docs/benchmarks/fastmath.md): vanilla's 64k table costs ~1 ns/op on modern hardware; the 4k variant measured slower and 16x less accurate. Nothing to gain. |
| Chunk updates per frame | Configurable rebuild budget | **in progress** | Lands with the multi-core pipeline (docs/ROADMAP.md #1). |
| Antialiasing (FSAA) | Smoother edges | **excluded** | Requires recreating the Display with a multisample pixel format (restart-only), and legacy-GL multisample contexts are unreliable under macOS's GL-on-Metal. Niche benefit, real platform risk. |
| Anisotropic filtering | Sharper angled textures | **matched by vanilla** | Vanilla 1.7.10 already ships AF in video settings; nothing to add unless bugs surface. |
| Mipmaps | Reduce distant texture shimmer | **matched by vanilla** | Vanilla 1.7.10 already ships mipmap levels; OptiFine-era fixes largely merged upstream. |

## Resource-pack visual features

These parse community-documented resource-pack formats (MCPatcher/OptiFine-convention `.properties`
files). File-format compatibility is an interoperability surface; implementations are original.

| Feature | Purpose | Vertex status | Notes |
|---|---|---|---|
| Connected textures (CTM) | Seamless glass/bookshelves etc. | **excluded (0.2.x)** | Attempted and blocked by a vanilla validation, with the exception recorded: `TextureMap.registerIcon` throws `IllegalArgumentException: Name cannot contain slashes!`, so tiles living under `mcpatcher/ctm/<name>/N.png` cannot be registered into the block atlas through the supported API - and without atlas coordinates no `IIcon` exists for a dispatch to return. The two remaining routes both carry costs this mod exists to avoid: injecting synthetic sprites into TextureMap's private registry plus loading their images by hand (deep reflection into stitcher internals, brittle across any change), or binding each tile as a standalone texture (a texture bind per face, destroying batching). The connectivity engine, format parser, rule indexing, pack scanner and 47-class tile ordering stay merged and tested (docs/OPEN-QUESTIONS.md records the finding), so a future revisit starts from working parts rather than from scratch. |
| Custom sky | Pack-defined sky boxes | **matched (mechanism)** (0.2.0) | End to end: numbered skyN.properties load on resource reload, and layers draw at the tail of the vanilla sky pass with day-clock fade, blend mode, and celestial rotation, restoring GL state and leaving depth writes off so terrain still occludes. Measured in-world: 5,766 and 5,929 draws across consecutive windows, zero failures. **Open seam:** the 3x2 face UV layout is mechanically verified but visually unconfirmed - it rides the same fly-through as multi-core. |
| Custom colors | Pack-defined colormaps | **matched** (0.2.0) | Feature-complete for the core use: pack grass/foliage colormaps load on every resource reload and the vanilla colorizers defer to them (conditional head override, vanilla path untouched without a pack). color.properties keys load and await per-key consumers (fog/sky/potions) as documented follow-up scope; visual confirmation rides the shared fly-through. |
| Emissive textures | Glow overlays | **excluded** | Requires drawing each face a second time at fullbright. Vertex's icon dispatch is a 1:1 sprite substitution point and cannot express a second draw; vanilla's nine face-render methods each tessellate one quad with one icon, so overlays would mean replacing them wholesale on the renderer's hottest path. Structurally worse in 1.7.10: chunk geometry bakes into per-pass display lists with brightness baked into vertex colors, so an overlay needs either a third chunk render pass (extra display list and draw call per chunk per frame) or duplicated per-face geometry inflating every chunk's vertex count - real frame-time cost for a cosmetic effect, in a mod whose purpose is performance. The naming core (EmissiveSuffix) stays merged and tested; if a future Vertex ever replaces the display-list renderer with a shader pipeline, emissive becomes a natural fit and this exclusion should be revisited. |
| Random entities | Per-mob texture variants | **matched** (0.2.0) | Numbered sibling textures (cow2.png, cow3.png, ...) discovered once per base texture by resource probing and cached; each mob picks deterministically from its entity id, so its appearance is stable for life. Measured in-world with a verification pack: 3 variants discovered, 28,307 and 29,585 bindings across consecutive windows, zero failures. Render-path cost is a map lookup plus an integer hash. |
| Natural textures | Mirror/rotation tiling variants | **matched (mirrors)** (0.2.0) | Deterministic per-position mirror variants (identity, horizontal, vertical, 180 rotation) via cached IIcon proxies on the shared dispatch. Measured in-world with a verification pack: 874,454 variant applications during world load, 3,375/min steady state, zero failures. **90/270 rotation excluded with cause:** the vanilla IIcon surface is nine methods exposing only min/max and interpolated U/V - it cannot swap the U and V axes, so a quarter turn would require per-corner UV control inside the tessellator, i.e. replacing vanilla's face renderers on the hottest path in the renderer. Packs declaring 4 rotations receive the 2-rotation treatment. |
| Better grass / better snow | Side-grass and snow-under-fence rendering | **matched (grass)** (0.2.0) | Grass sides render the top texture where terrain continues below. Status restored after a controlled A/B: identical build, pack disabled 172,098 icon resolutions/min and armed; pack enabled 155,957 and armed. Config-gated, default off. Better snow is documented follow-up scope on the same dispatch. |
| HD fonts / HD textures | Pre-1.6 McPatcher features | **excluded** | Vanilla's 1.6+ resource pack system already supports arbitrary resolutions and fonts; nothing left to implement for 1.7.10. |

## Platform and infrastructure

| Feature | Purpose | Vertex status | Notes |
|---|---|---|---|
| Standalone tweaker install (no Forge) | Single-mod loader via LaunchWrapper | **matched** | `--tweakClass vertex.VertexTweaker` + profile installer since 0.1.0. |
| Configuration | Persistent user settings | **matched** (0.2.0) | `vertex.properties` in the game dir, hot-reloaded (~1s); no GUI yet (see excluded). |
| In-game options GUI | Video-settings screens | **surpassed** (0.4.x) | Demand appeared; revisited. The vanilla Video Settings screen is rebuilt into the six-page OptiFine 1.7.10 layout (Video / Details / Animations / Quality / Performance / Other): vanilla options keep their real widgets, labels and persistence (including real GuiOptionSliders), Vertex features are wired through vertex.properties (fullbright sits in the reference's Shaders slot, Chunk Loading maps to `multicore`), and reference slots with no real backing render disabled rather than faking behavior. Sub-pages are real screen instances so Done/Esc walk back exactly like vanilla; layout is pure data locked by unit tests and verified against the reference screenshots by the six-page GUI probe. The config file + hot reload remains authoritative for every key. |
| Shaders support | Programmable-pipeline visual overhaul | **excluded (for now)** | Requires replacing the fixed-function display-list renderer with a deferred, shader-driven pipeline - effectively a new renderer, not a patch. The 0.4.0 renderer-backend ladder now supplies the multi-core/VBO groundwork; what remains is the shader pipeline itself, still out of scope. Documented as the boundary of the project's ambition for 1.7.10. |
| Show FPS / lagometer / debug diagnostics | Performance visibility | **in progress** (0.2.0) | Periodic activity counters land with `diagnostics=true` (promotions, rebuilds, active skips, once/minute). HUD and frame-time metrics later. |
| Crash-resilient hooks | A broken patch must never take the game down | **surpassed** | Every transformer falls back to vanilla bytes; every hook self-disables on first failure and logs once. OptiFine historically hard-crashes on patch mismatch. |
| Forge compatibility | Coexist with Forge | **excluded** | Vertex targets the obfuscated vanilla client by design; under Forge, names differ and Vertex deliberately no-ops. Forge users have the mod ecosystem for these features. |
| Cape support | Cosmetics | **excluded** | Not a performance feature; out of scope. |

## Priority queue (by impact / effort, as of 0.4.0)

1. Renderer-backend real-world miles toward a default-on decision (same promotion gate multicore passed)
2. Immutable section snapshots for worker builds - removes the last live-renderer race class (docs/ROADMAP.md #1)
3. Chunk-update budget policy (smooth/lazy loading) on the build queue
4. Connected textures revisit: atlas sprite injection is the single blocking piece (docs/ROADMAP.md #2)
5. Diagnostics HUD (on-screen frame time and pacing)
6. Better snow; dropped-item and burning-entity dynamic lights; per-key custom-colors consumers
